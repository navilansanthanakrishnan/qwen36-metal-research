Plain decode is closed — 16.40 tok/s is the one-token-per-pass ceiling and no kernel beats it. Everything above that line comes from accepting more tokens per forward pass, which is why every speculative number here is reported with its acceptance rate beside it.

The new kernel

Q4_K mat-vec that dequantizes directly into simdgroup matrix registers and multiplies on the matrix units, with no threadgroup traffic. No llama.cpp backend does this: mul_mv and mul_mv_ext are register-resident but scalar, and mul_mm uses the matrix units but stages dequantized weights through threadgroup memory — which is why it costs the same as mat-vec at these widths.

Two things made it possible, and both had to be measured rather than looked up. thread_elements() is writable, and its lane→element layout is implementation-defined, so it was recovered empirically: row = 4·(lane/16) + (lane%8)/2, col = 4·((lane%16)/8) + 2·(lane%2). And the sum over K is order-invariant, so the map from fragment column to element is free to choose — picking elem = k·4 + t turns a lane's eight weights into one aligned 8-byte load.

The cost model, and what it demands

cycle = T_ver + (D+1) · t_draft   →   t_draft = 8.9 ms, T_ver = 122.4 ms

Solved from the depth-4 and depth-7 measurements; it predicts depth 5 within 3%. 35 tok/s at depth 4 needs a 94.1 ms cycle. Drafting is only 44.5 ms of the current 166.9 — so making drafting entirely free would still not be enough, because T_ver alone exceeds the whole budget. Two things must both happen:

  1. T_ver 122 → ~90 ms. The standalone probe runs this kernel at 170 GB/s against a 212.9 GB/s loads-only ceiling measured for its own access pattern, so ~25% remains inside the kernel.
  2. mean_acc/fwd 3.65 → ~4.7. Depth cannot supply it: each extra draft step buys about 0.12 accepted tokens and costs 8.9 ms.
Tree drafting is the lever the flat kernel actually unlocked. Verify at width 8 now costs what width 5 costs, so a tree of 8 candidates is as cheap as today's chain of 5. That raises accepted-tokens-per-forward without adding draft steps — precisely the term the model says is missing.
